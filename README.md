# Дневник путешествий (Кейс-задача № 3.2)

Технологическая (проектно-технологическая) практика.ИСиТ_ВР(6)(1/3)_2509 Кейс-задача №5

## Функциональность

- Регистрация и вход (сессии)
- Создание записи о путешествии с:
  - Местоположением (текстовое поле)
  - Загрузкой изображения
  - Стоимостью
  - Описанием
  - Отметкой о публичности
- Просмотр всех публичных записей других пользователей
- Просмотр своих записей (включая приватные)
- Удаление своих записей

## Технологии

- Node.js + Express
- express-session (аутентификация)
- multer (загрузка файлов)
- JSON-файлы для хранения данных

## Установка и запуск

1. Установите [Node.js](https://nodejs.org/) (версия 14+).
2. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/ItsukaKotoriii/travel-diaryCase5.git
3. Перейдите в папку проекта:
    cd travel-diary
4. Установите зависимости:
    npm install
5. Запустите сервер:
    node server.js
6. Откройте браузер по адресу: http://localhost:3000

## Анализ
1. Архитектура – Приложение на Node.js + Express. Данные хранятся в JSON-файлах, загруженные изображения – в папке uploads/. 

2. Аутентификация – реализована через сессии. Пользователь может зарегистрироваться и войти. Однако пароли хранятся в открытом виде.

3. Создание записи о путешествии – реализованы три выбранные функции: местоположение (текстовое поле), загрузка изображения и стоимость. Также добавлено описание и флаг публичности. Запись сохраняется в travels.json.

4. Просмотр записей других пользователей – доступна лента всех публичных записей с указанием автора. Приватные записи видны только их создателю. 

5. Просмотр деталей записи – реализовано модальное окно с полной информацией (фото, описание, стоимость, дата, автор). Возможность удаления только для владельца записи.

6. Работа с изображениями – файлы загружаются на сервер, сохраняются с уникальным именем, путь хранится в JSON. При удалении записи файл удаляется с диска.

7. Интерфейс – разделение на вкладки (все записи, мои записи, новая запись). 

## Рекомендации по устранению ошибок
1. Добавить хеширование паролей.

2. Валидация данных на сервере – проверять, что местоположение не пустое, стоимость – положительное число, описание не слишком длинное. Возвращать понятные ошибки.

3. Переход на базу данных – заменить JSON-файлы на SQLite или PostgreSQL. 

4. Добавить редактирование записей – сейчас можно только удалять. Необходимо реализовать возможность изменения существующих записей (обновление текста, стоимости, фото).

5. Улучшить обработку ошибок – добавить централизованный обработчик ошибок, логирование ошибок в файл.

6. Адаптивная вёрстка – использовать медиазапросы для корректного отображения на мобильных устройствах.

7. Безопасность загрузки файлов – ограничить размер и типы загружаемых изображений, предотвращать загрузку исполняемых файлов.
